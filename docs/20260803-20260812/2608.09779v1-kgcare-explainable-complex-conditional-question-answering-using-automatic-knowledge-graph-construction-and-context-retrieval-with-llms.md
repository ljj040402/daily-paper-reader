## 摘要
使用大型语言模型（LLM）和检索增强生成（RAG）回答复杂条件问题仍然是一个挑战，尤其是在通用LLM和RAG往往表现不佳的特定领域情境中。我们假设，通过将RAG与从文档和知识图谱（KG）中提取的非结构化与结构化知识增强，可以提高此类任务的推理和答案准确性。为验证这一点，我们提出了KGCaRe，一种将神经检索与基于LLM生成的知识图谱上的符号推理相结合的混合方法。KGCaRe使用多提示词提取策略从文档构建知识图谱，并将其存储在图数据库中。同时，文档被嵌入到向量存储中以实现神经检索。KGCaRe执行由LLM引导的创新性迭代图遍历，以提取相关三元组、剪除无关信息，并在初始遍历未能提供足够上下文生成答案时，利用额外线索实体再次遍历图。从知识图谱中提取的路径形式的相关三元组，连同语义检索到的文本段落，被输入到定制的KGCaRe提示词中，以生成复杂条件问题的答案及解释。我们在两个复杂条件问答数据集上评估了KGCaRe。在这些数据集上的结果表明，在Mistral、Mixtral、GPT-3.5和GPT-4o等多个LLM上，KGCaRe始终优于现有基线方法，包括Vanilla LLM、Code Prompt、Text Prompt、Think-on-Graph、Vanilla RAG和HybridContextQA。我们公开了为实现所提出的KGCaRe方法而开发的软件流水线。

## Abstract
Answering complex conditional questions using Large Language Models (LLMs) and Retrieval-Augmented Generation (RAG) remains a challenge, particularly in domain-specific contexts where general-purpose LLMs and RAG tend to underperform. We hypothesize that augmenting RAG with unstructured and structured knowledge, extracted from both documents and knowledge graphs (KGs), can improve reasoning and answer accuracy for such tasks.   To test this, we propose KGCaRe, a hybrid approach that combines neural retrieval with symbolic reasoning over LLM-generated KGs. KGCaRe constructs a KG from documents using a multi-prompt extraction strategy and stores it in a graph database. Simultaneously, the documents are embedded into a vector store to enable neural retrieval. KGCaRe performs innovative iterative graph traversal guided by the LLM to extract relevant triples, prune irrelevant information, and uses additional clue entities to traverse the graph again if the initial traversal does not provide satisfactory context to generate the answer. The relevant triples extracted from the KG in path form, along with semantically retrieved text passages, are then fed into custom KGCaRe prompts to generate answers to the complex conditional questions with explanations.   We evaluate KGCaRe on two complex conditional QA datasets. Our results on these datasets show that KGCaRe consistently outperforms existing baselines, including Vanilla LLM, Code Prompt, Text Prompt, Think-on-Graph, Vanilla RAG, and HybridContextQA, across multiple LLMs such as Mistral, Mixtral, GPT-3.5, and GPT-4o. We publicly release the software pipeline that we developed to implement the proposed KGCaRe approach.

## 一、核心问题与研究动机

- **研究背景与问题**：在特定领域场景中，LLM 与 RAG 在处理**复杂条件问答**（complex conditional QA）时性能显著下降。原因包括：（1）模型缺乏领域专用语料的微调；（2）上下文不足时 LLM 容易产生“幻觉”（hallucination）；（3）条件问题对隐含约束高度敏感——问题中的条件常常未显式提及，而需要在文档各部分中通过多跳推理才能组装出来，LLM 难以隐式捕捉这类依赖。
- **核心假设**：将**非结构化知识**（文档原始文本的语义检索）与**结构化知识**（从同一文档构建的知识图谱）同时注入 RAG，可以显著改善复杂条件问题的推理质量和答案准确性。
- **整体含义**：作者提出 **KGCaRe** 方法，用 LLM 自动从文档构建知识图谱并结合向量语义检索，以兼顾符号推理的精确性和神经检索的语义灵活性，在复杂条件问答任务上提升答案质量、条件识别能力和可解释性。

## 二、方法论：KGCaRe 框架

KGCaRe 是一个端到端模块化流水线，核心设计如下：

1. **多提示词知识图谱构建（Multi-Prompt Triple Extraction，四阶段）**
   - **阶段一**：LLM 深度分析文本，识别关键实体与关系，提取细粒度、上下文感知的三元组，如 `('Applicant', 'must submit', 'form')`。
   - **阶段二**：专家聚焦条件逻辑——显式捕捉 if-then 结构、例外情况和替代方案，补充条件型三元组，如 `('Consent', 'not given', 'get permission from court')`。
   - **阶段三**：对已提取三元组进行完整性验证、特异性增强与逻辑互链，利用传递或隐含逻辑推导新三元组。
   - **阶段四**：将最终三元组标准化后导入 **Neo4j** 图数据库，支持大规模存储与高效遍历。

2. **语义向量索引**
   - 并行地将原始文档嵌入为高维向量，存入 **FAISS** 索引，支持基于查询相似度的快速近似最近邻检索，用于补充 KG 未能捕获的全局语义上下文。

3. **KG 遍历算法（Algorithm 1）**
   - 从问题中提取主题实体（`E_topic`）作为锚点，以深度限制（`D`）进行迭代遍历。
   - 第一层使用**部分匹配**（subword matching）保证宽泛探索，后续层使用**精确匹配**保证聚焦。
   - 并行地围绕“线索实体”（`E_clue`）做部分匹配，以发现主题实体未能覆盖的支持性证据（该思路受 Tree-of-Traversal 启发）。
   - 每轮提取的三元组经 **LLM 驱动的剪枝函数**（`PruneTriples`）过滤，保留最相关的候选，并记录到三元组记忆 `M`、路径记忆 `M_path` 中。
   - 然后用 LLM 进行**推理判断**：若信息足以回答则停止；否则让 LLM 生成新的线索实体继续下一层遍历；若线索耗尽或没有相关三元组，则触发**回退模式**，让 LLM 直接对问题推理提取新线索。
   - 达到最大深度或获得足够上下文后停止，返回 KG 上下文。

4. **融合检索与答案生成**
   - 将 KG 路径形式的三元组和 FAISS 语义检索的 top-k 段落同时格式化到定制提示词中，交给 LLM 生成最终答案。
   - 提示词显式要求模型从两方证据合成答案，并在适用时指出答案成立的前提条件——这对条件型问题至关重要。
   - 整个遍历过程保留了显式推理轨迹（访问过的实体、剪枝、遍历路径），保证答案的**可解释性与可审计性**。

## 六、主要结论与发现

- **总体有效性**：在两个数据集上、对四种 LLM，KGCaRe 在平均 F1（Avg F1 Score）上**全部超越所有基线**，验证了“结构化+非结构化混合上下文”的假设。
- **关键数字**：
  - ConditionalQA上：Mistral 57.89 vs. 最优基线 45.17；Mixtral 59.45 vs. 53.71；GPT-3.5 60.01 vs. 57.79；GPT-4o 67.55 vs. 63.71。
  - HotpotQA 上：GPT-3.5 从 61.84 提升至 **71.48**，GPT-4o 从 73.37 提升至 **80.21**；在弱模型上同样显著。
- **问题类型分析**：KGCaRe 在 Conditional 类型问题上增益最大（弱 LLM 场景）；消融实验表明在唯一正确答案的 Yes/No 子集上，KGCaRe 对 4 种 LLM 均获得最高 F1（如 Mistral 69.81、Mixtral 82.07、GPT-4o 88.67）。
- **对 Think-on-Graph 的批判性发现**：纯 KG 方法（ToG）在所有模型和数据集上表现最差，甚至在 HotpotQA Yes/No 上出现 F1=0（因为模型生成长文本而未包含“yes/no”词），说明符号遍历在无文档补充时不足以支撑复杂条件问答。这正是 KGCaRe 的核心差异点——用向量补全 KG 的稀疏或噪声问题。
- **可解释性**：KGCaRe 通过展示 KG 遍历路径，为答案提供人类可理解的逻辑链条（如“申请人需在退休年龄以下且居住在英国”），增强了透明性与信任度。

## 七、优点

1. **混合检索设计兼具精确性与灵活性**：符号遍历提供逻辑骨架，FAISS 语义检索补偿 KG 的稀疏性，两者优势互补。
2. **可解释性强**：完整记录信息保留整个推理链路（路径、剪枝、条件），而非仅给出黑盒答案，适合法律、政策等高风险场景。
3. **对弱 LLM 显著增强**：在 Mistral 等小模型上提升幅度最大（约 12 个 F1 点），说明该方法能有效弥补模型能力不足。
4. **多阶段 KG 构建**：专门设计“条件与例外”提取阶段，贴近真实政策/法务文本的逻辑结构，保证三元组质量。
5. **工程完整度较高**：代码、提示词、KG 数据全部公开，便于复现和后续扩展。

## 八、不足与局限

1. **评估范围有限**：HotpotQA 只评估 500 对（非全量开发集）；ConditionalQA 测试集不可用，因此只用了开发集；未在更多领域（如医疗、金融）验证泛化能力。
2. **遗漏关键对比方法**：未与 RoG、Think-on-Graph 2.0、Tree-of-Traversal 等更强的新 SOTA 方法对比，证明“相对优势”的力度有所折扣。
3. **计算成本不可忽略**：KG 构建需多提示词多轮 LLM 调用，且推理时每层图遍历都要调用 LLM 进行剪枝和推理判断，延迟和 API 成本未报告，可能限制工业落地。
4. **KG 构建误差级联**：KG 由 LLM 提取，若提取错误或缺失（7,031 条三元组对 271 篇文档规模较小），下游遍历和回答质量将受传导影响；论文未提供三元组抽取的准确率/人工评估。
5. **确定性不足**：GPT 系列采用 LlamaIndex 默认 temperature=0.7，结果存在随机浮动；未报告多次运行的平均值和标准差，公平性严格性稍弱。
6. **超参敏感度未分析**：最大深度、top-k、max_entities 等关键参数对性能的影响未做敏感性分析，默认值是否稳健存疑。
7. **部分类别优势不明显**：在 GPT-3.5/GPT-4o 的 Yes/No 部分问题上，KGCaRe 与 HybridContextQA 或 Text Prompt 差距甚微（甚至被反超一次），说明高容量 LLM 场景下混合检索带来的边际收益有限。
