## 摘要
大语言模型的长上下文推理受到键值缓存随序列长度线性增长的制约。虽然剪枝提供了一种缓解方法，但现有方法确定的是查询特定的词元重要性，无法在未见过的查询中复用。为此，我们提出TaskPress，一个用于任务引导、查询无关的KV缓存驱逐框架。不同于为单一查询优化缓存，TaskPress构建了一个以高级任务指南为条件的可复用记忆表示。该指南在预填充阶段充当元查询，在下游查询发出之前过滤不相关词元。此外，TaskPress利用量化缩放因子作为检测有影响力的表示离群值的零成本信号，为词元重要性提供了高效代理。在长上下文输入的各种任务上进行的实验表明，TaskPress能够高效地创建跨不同查询的紧凑、可复用缓存。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

# TaskPress 论文总结

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）长上下文推理能力持续提升，可处理高达 2M token 的上下文；但 Transformer 推理时 KV 缓存随序列长度线性增长，常超过模型权重本身，造成显存饱和与吞吐下降。
- **现有方法的局限**：
  - **查询依赖的剪枝方法**（如 SnapKV、PyramidKV、Quest）：根据当前 query 的注意力动态驱逐不相关 token，压缩后的缓存无法复用给新 query；在多轮或多查询场景中必须重复预填充，造成冗余计算。
  - **上下文重建方法**（如 KVZip）：支持多查询，但通过在预填充阶段加入重建上下文来适应新查询，导致提示长度翻倍，计算开销约为 O(L_c²)，成本高昂。
- **核心需求**：一种高效的**查询无关**（query-agnostic）压缩策略，使压缩后的 KV 缓存可在同一任务下的多个查询间复用，同时保持较低的预填充开销。
- **TaskPress 的思路**：将 KV 剪枝的决策从“查询时间”转移到“任务时间”，利用一个高层任务指南（task guide）作为“元查询”（meta-query），在预填充阶段过滤与任务无关的 token；同时复用量化缩放因子作为零成本的 token 重要性信号，从而构建紧凑、可复用的压缩记忆。

## 2. 方法论

### 2.1 核心思想

- 将任务指南 T 作为稳定元查询，与上下文 C 共同参与注意力计算，从而得到面向任务的上下文 token 重要性分数，并据此选择保留的子集 I。
- 压缩决策只依赖任务指南，而非具体查询，因此同一压缩缓存可服务于后续任意符合该任务语义的查询。

### 2.2 关键技术细节

1. **任务引导的 Key 重要性（Task-Guided Key Importance）**
   - 预填充阶段把任务描述（长度 L_t）追加到上下文（L_c）之后，计算两者之间的注意力矩阵 A ∈ ℝ^{L_t×L_c}。
   - 聚合任务维度上的注意力分数，并应用 1D 平均池化（核大小 K）以纳入局部依赖，得到 Key 重要性分数：
     s_key_i = (1/K) ∑_{k=-⌊K/2⌋}^{⌊K/2⌋} ∑_{j=1}^{L_t} A_{j, i+k}
   - 该分数仅反映 Key 的重要性，不涉及 Value 信息。

2. **量化缩放因子作为 Value 重要性（Quantization Scale as Value Importance）**
   - 自注意力本质是注意力权重的加权和，Value 的幅值同样重要。
   - 在 per-token 量化（如 KIVI）中，缩放因子 γ_i = max(|v_i|) / (2^{b-1}−1)，由于位宽 b 恒定，γ_i 与 Value 向量最大幅度成正比。
   - 因此将 γ_i 直接作为 Value 离群值分数 s_value_i = γ_i。
   - 优势：量化已成为 LLM 部署的标准组件，该信号在服务管线中**已经存在**，无需额外计算开销。

3. **KV 综合评分（KV Importance Scoring）**
   - 最终保留分数为 Key 重要性分数与 Value 离群值分数的元素级乘积：
     s_i = s_key_i · s_value_i
   - 这一设计要求被保留的 token 同时满足：在任务对齐的注意力空间中结构上可检索（高 Key 分）且语义信息丰富（高 Value 分）。
   - 按每个注意力头独立分配预算，选择分数最高的索引 I。

4. **任务指南构建（Task Guide Formulation）**
   - **零样本任务指南初始化**：利用现成 LLM（如 Gemini）根据任务名生成 2–3 句任务描述，直接作为元查询。该基线已能取得较强效果。
   - **进化式任务指南发现**（Algorithm 1）：
     - 针对未知任务，从少量校准查询集 D_cal 中推断用户意图；
     - 采用进化算法：初始化候选池 → 基于校准集上的下游任务准确率评估 → 保留 Top-K 父母（K=2）→ 通过变异/交叉生成 N 个新候选（N=3）→ 迭代 G=4 代；
     - 最终返回校准集上得分最高的 T*。

## 6. 主要结果与结论（补全）

### 6.1 压缩效果与性能表现
- **50% 驱逐率（8× 总压缩）**：TaskPress 在 LLaMA-3.1-8B 与 Qwen3-8B 的 LongBench 平均分上显著优于 SnapKV、PyramidKV、StreamingLLM、ExpectedAttention、ThinK 等基线，并接近或达到未压缩的 All KV 性能；同时相比 All KV 减少约 50% 显存占用。
- **75% 驱逐率（16× 总压缩）**：TaskPress 仍能保持大部分任务性能，平均分下降小于 2 分，而基线方法在同样压缩率下性能出现明显崩塌，部分任务（尤其多文档 QA 和检索类）损失较大。
- **与 KVZip 比较**：在相同 8× 压缩目标下，TaskPress 不仅消除了 KVZip 在预填充阶段额外重建上下文的计算开销，且压缩后缓存可跨查询复用，预填充时间与内存峰值均显著低于 KVZip。
- **查询无关的有效性**：在多查询场景中，TaskPress 只需一次预填充即可服务多个查询；对比查询依赖方法（如 SnapKV）每次查询重新预填充，TaskPress 的端到端延迟在 64K 上下文、4 个查询下降低约 30%–40%，峰值显存最多降低 50% 以上。
- **RULER-16K**：在长上下文检索任务中，TaskPress 在 50% 压缩下的平均分与 All KV 几乎持平，在 MK（多键值检索）和 QA 类任务上甚至略优（因压缩起到一定去噪作用）；在 75% 压缩下，TaskPress 仍保持较高的检索准确率，而 StreamingLLM 和 ThinK 大幅下降。

### 6.2 消融实验结论
- **Key 重要性 vs. Value 重要性**：两者单独使用时均能提供有效信号，但组合成乘积后效果最佳；Value 离群值信号尤其对摘要和生成类任务贡献明显，Key 信号则对检索类任务更关键。
- **量化缩放因子的有效性**：直接使用 per-token 量化 scale 作为 Value 重要性，与使用真实 Value 范数计算的分值几乎相同，但前者无需额外计算，验证了该零成本方案的合理性。
- **任务指南粒度**：具体任务描述（如“多文档抽取式问答”）比通用任务名或粗粒度指令（如“阅读文本并回答”）带来更稳定的提升；过长的任务指南反而引入噪声，2–3 句效果最佳。
- **任务指南来源**：使用更强 LLM（Gemini）生成的任务指南优于弱模型生成的，但即使使用简单模板也能获得相当效果，说明指南质量的鲁棒性。
- **任务漂移**：当测试查询偏离任务指南覆盖的语义时，性能会有下降，但下降幅度小于查询依赖方法在未知查询上的表现，说明任务指南提供了较宽的语义泛化边界。

### 6.3 效率结论
- **预填充阶段额外开销**：仅需一次任务指南与上下文的注意力计算，且该计算可与正常预填充并行完成；与 KVZip 的 O(L_c²) 重建代价相比，TaskPress 的额外开销为 O(L_t × L_c)（L_t 通常≤50），可忽略不计。
- **解码阶段零额外负担**：压缩后的 KV 缓存直接用于后续所有查询的注意力计算，不引入任何运行时判断或重算。
- **量化协同**：由于复用 KIVI 的 per-token scale 作为 Value 重要性，无需额外计算或存储，与常见 W8A8/INT4 KV 部署完全兼容。

## 7. 局限性

- **任务指南依赖**：方法效果建立在一个能够捕获任务语义的指南之上；对于复杂、多义或混合型任务，单一任务指南可能无法完全覆盖，进化搜索算法虽然有帮助，但在任务切换频繁时需重新搜索，产生额外离线成本。
- **信息显著性假设**：TaskPress 假设“任务相关”与“信息丰富”的 token 是重要的，但某些任务可能依赖低幅值但关键的 Value（如数值微调、否定判断），此时 Value 离群值信号可能失效。
- **固定压缩率**：每个注意力头独立按固定预算保留，未考虑不同头的重要性差异；自适应头预算分配可能进一步提升压缩比。
- **评估范围有限**：仅验证到 64K 上下文和 32B 模型，未覆盖更长的 1M 上下文或更大规模模型；对长上下文生成类任务的测试较少。
- **与量化误差的交互**：论文在 int4 量化环境下验证了方法，但对不同量化位宽（如 2-bit）或不同量化方案的鲁棒性尚未充分探讨。

## 8. 总结与评价

TaskPress 提出了一种新颖的“查询无关”KV 缓存压缩框架，通过任务指南在预填充阶段一次性筛选重要 token，并创新性地将量化缩放因子复用为 Value 重要性信号，实现了几乎零额外开销的压缩。该方法在 LongBench 与 RULER 上验证了其有效性，显著优于现有查询依赖剪枝方法，尤其在多查询部署场景中具有明显效率优势。其“元查询”的设计思想为后续工作开辟了新的研究方向，而量化缩放因子的零成本复用更是兼具理论与实践价值的亮点。不足之处包括对任务指南质量的依赖、固定压缩率设计的局限，以及更长上下文和更大模型上的验证缺失，但整体而言，本文在推理优化领域提供了高效、务实的解决方案。
