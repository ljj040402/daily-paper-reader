## 摘要
我们提出了一种基于模式的框架，利用生成式AI从非结构化文本中提取复杂、结构化信息，并随后对提取的信息与金标准进行自动语义评估。该模式作为编码领域知识的信息模型，为提取具有可变基数属性的分层嵌套信息，以及随后对结果进行评估，提供了统一、系统且一致的框架。对文档的信息提取在零样本模式下通过单次模型调用完成。在评估步骤中，我们引入了一种基于路径的语义匹配算法，将提取结果中的嵌套、可变基数属性与金标准中的属性对齐。我们使用生成式AI对属性的提取值与金标准值进行语义比较，并引入一个评分标准，根据特定领域的考虑，将比较结果分类为完全匹配、语义匹配、有用匹配或不匹配。我们使用生成式AI模型Claude Opus 3，从健康技术评估组织NICE发布的文档中成功提取了14个属性中的12个，F1分数超过90%。从文档中提取属性所需的时间比人类领域专家所需时间低约30倍。我们进一步证明了该框架在不同生成式AI模型上的通用性，以及在不同HTA组织和语言之间的可迁移性。

## Abstract
We present a schema-based framework for extracting complex, structured information from unstructured text documents using generative AI, followed by automated semantic evaluation of the extracted information against a gold standard. The schema, serving as an information model encoding domain knowledge, provides a unified, systematic, and consistent framework for extraction of hierarchical, nested information, with attributes of variable cardinality, and subsequent evaluation of the results. Information extraction from a document is performed in a single call to the model, in zero-shot mode.   In the evaluation step, we introduce a path-based semantic matching algorithm to align the nested, variable-cardinality attributes in the extracted results with those in the gold standard. We use generative AI for semantic comparison of the extracted and gold standard values of an attribute, and introduce a rubric to classify the result of the comparison, according to domain-specific considerations, as an exact, semantic, useful, or non-match.   We were able to extract 12 out of 14 attributes with an F1 score of $>$90\% from documents published by the health technology assessment organisation NICE, using the generative AI model Claude Opus 3. The time needed to extract the attributes from a document was $\sim$30 times lower than the time taken by a human domain expert. We further demonstrate generalisability of this framework across different generative AI models and transferability across different HTA organisations and languages.

### 二、论文提出的方法论

#### 核心思想
- 以**模式图（schema）作为统一信息模型**，编码领域知识，贯穿提取、输出格式化和评估全过程。模式图同时承担三重角色：编码领域信息（属性定义、约束、枚举值）、指定输出格式（嵌套JSON结构）、提供评估上下文（属性名称和描述）。
- 提取阶段采用生成式AI模型，**零样本、单次调用**即可从整篇文档（20-40页）中提取全部属性。

#### 关键技术细节
- **模式设计**：采用JSON Schema格式，通过`type`字段指定属性类型（string/array/object/null）；通过`pattern`字段强制格式（如日期格式）；通过`enum`字段限制取值（如"positive"/"negative"/null）；通过嵌套结构表达层级关系（`indications`和`technologies`为字典列表，其中`indication_name`、`inn`、`brand_name`作为标识属性）。
- **提取流程**：开发集上人工制定金标准，将PDF文档转换为文本后，结合指令、模式图和文档文本构造单一提示词，调用Claude Opus 3 API，temperature参数设为0以保证确定性输出。
- **评估算法**：提出**基于路径的语义匹配算法**。对嵌套JSON结构，通过路径定位叶子属性；对于列表中的字典元素，利用锚属性（anchor attribute）寻找最佳1:1匹配；若存在多个可能匹配则按匹配类型优先级（exact > semantic > useful）排序后进行贪心选择。
- **语义比较分级**：当字符串精确匹配失败时，使用生成式AI（Claude Opus 4.6）将比较结果分为四类：
  1. **精确匹配（Exact）**：微小格式差异（如破折号、符号差异）；
  2. **语义匹配（Semantic）**：词汇不同但含义相同（同义改写）；
  3. **有用匹配（Useful）**：信息对比较研究仍有用（如“儿童发热”vs“12岁以下儿童发热”）；
  4. **非匹配（Non-match）**：无语言或语义相似性。
  - 前三种匹配均分类为TP，非匹配分类为FP。

1. **高提取性能**：在NICE文档上，14个属性中12个属性的F1分数>90%。表现较差的属性为`outcome_rea`（F1=0.88，因文档中相对有效性讨论模糊、语义含糊）和`clinical_restrictions`（F1=0.83，因与`indication_name`在文档推荐部分紧密耦合难以拆分）。

6. **关于Claude Opus 4.6的表现**：其性能略低于Claude Opus 3，原因在于提取粒度过细——生成结果比金标准更细致，提示需要显式指定输出的粒度级别。

### 七、优点

1. **统一的schema框架创新性强**：将模式图同时用作信息模型、输出格式规范和评估上下文基准，单一schema贯穿全流水线，逻辑统一、系统一致。
2. **单次零样本调用提取复杂嵌套结构**：避免了传统方法中需要逐属性构建规则或训练模型的繁琐流程。
3. **提出新颖的评估方法论**：基于路径的匹配算法有效解决嵌套、可变基数属性的对齐问题；rubric四类分级（exact/semantic/useful/non-match）充分考虑了领域实际需求（HTA研究对“有用匹配”的容纳）；采用“AI评估+人工复核”的方式，验证了AI评估的可靠性。
4. **多维度实证评估**：涵盖性能、一致性、成本、模型泛化、跨组织迁移等多个维度，实验设计较为全面。

### 八、不足与局限

1. **金标准主观性风险**：金标准由唯一领域专家创建，而人工提取本身存在主观性和误差，缺少多专家交叉验证和信度分析（如inter-rater reliability）。
2. **专有模型依赖**：使用Claude Opus 3（专有模型），依赖模型提供商的服务可用性、定价策略和模型存续状态。且模型漂移可能影响长期复现性和管线可持续性。
3. **粒度不一致问题**：Claude Opus 4.6提取粒度过细导致性能表现反而下滑，提示同一schema在不同模型间可能需要调整提示词以统一粒度，这削弱了一定的“即插即用”性。
4. **属性覆盖的领域偏好**：prompt是在NICE文档上开发的，对NICE表现最优；对ZIN和HAS迁移中部分属性表现仍有差距，尤其HAS不报告某些属性（内部标识符、成本效果）时的系统适配有待改进。
5. **生成式AI评估的偶然一致性**：尽管对AI的分类进行了人工复核，但exact/semantic/useful三类之间的区分在不同场景下可能有争议。
